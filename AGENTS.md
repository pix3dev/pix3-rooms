# AGENTS.md — binding rules for code in pix3-rooms

Read [`docs/architecture.md`](docs/architecture.md) (module map, cross-module seams, ownership) and [`docs/protocol.md`](docs/protocol.md) (byte-exact wire contract) before writing code. They are the contract; this file is the code-rule set.

## The one requirement that shapes everything

**600 concurrent players in one room, 2D top-down shooter, no lag.** Every design decision on the tick path answers to it:

- **AOI is core.** Broadcast-all at 600 players is ~4.3 Gbit/s. Each client receives only the ~30–50 entities near it.
- **Encode-once, memcpy-many.** A dirty entity is serialized exactly once per tick; per-client frames are assembled by copying those byte ranges. Never re-serialize per recipient.
- **Zero allocation per tick.** Structure-of-arrays state, pre-allocated buffers, `ArrayPool<byte>` frames, bitsets for visibility. At 20 Hz × 600 clients, one allocation per client per tick is 12 000 allocations/second of pure GC pressure.
- **Room = isolated unit** of state, scheduling and budget. One heavy room must never stall another.

## Layering

`Protocol` ← `{Net, Auth, Rooms, Replication, Admin, Observability}`. `Net` → `Rooms` + `Auth`; `Rooms` → `Replication` + `Net`; `Admin` → `Rooms`. `Replication` depends on `Protocol` only and must stay unit-testable with no sockets. Never introduce a dependency that reverses these arrows.

Nothing game-specific enters this repo — no players, HP, weapons, bullets or scores. An entity is `(netId, owner, kind, transform, flags, cold props)`. If a change would make sense only for one genre, it belongs in the pix3 runtime or in a Level-2/3 rules module, not here.

## Threading contract

- Room logic is **single-threaded**. Socket threads never touch room or replication state directly — they hand work over through the room's inbound channel. If you need to read room state from a socket thread, you need a message, not a lock.
- Membership dictionaries are the deliberate exception (joins/leaves originate off-thread); they are concurrent collections and nothing else in the room may be.
- Buffer ownership transfers explicitly: whoever successfully enqueues a pooled buffer gives it up; whoever fails to enqueue must return it. Every error and drop path returns its buffers. Double-return is worse than a leak.

## Style

- Nullable is on and nullable warnings are **errors**. Restructure rather than reaching for `!`.
- Dependencies are frozen: `MemoryPack` (Protocol), `Microsoft.IdentityModel.JsonWebTokens` (Auth), xUnit + `Microsoft.AspNetCore.Mvc.Testing` (tests). Metrics are hand-rolled Prometheus text. Adding a package needs a reason in the PR description.
- Hot path (called per tick per entity, or per tick per client): no LINQ, no closures, no `async`, no interface-dispatched enumerators, no string formatting — `Span<byte>` writers and plain loops. Control path may be idiomatic.
- Readers of untrusted bytes return `bool` and never throw. Malformed input is a normal event, not an exception.
- Never trust client-supplied ids, ticks or masks. Validate ownership on every entity mutation.
- Every close that has a known reason sends a `RejectEvent` first, so the client can show a real message instead of "connection lost".
- Log with room id and tick context. Never swallow an exception silently; a room that throws repeatedly is destroyed and its clients closed with `InternalError`, not left half-alive.
- XML doc comments on public seam members. Inline comments explain *why*, never *what* — and always where a subtle invariant is being upheld (generation reuse, Known-set updates, buffer ownership).

## Tests

A change to a byte layout must come with updated **golden vectors** (hardcoded expected bytes derived from `docs/protocol.md` by hand — never generated by the code under test) and a `ProtocolVersion` bump.

The replication core's correctness properties are regression-tested and must stay green: no delta without a prior full record; generation reuse rejected; enter+dirty in one tick sends a full record only; frame-size cap neither loses nor duplicates entities; encode count equals dirty-entity count, not dirty × subscribers. Room isolation (two rooms, zero cross-talk) is likewise a permanent test, because that is precisely what the predecessor server got wrong.

Run `dotnet build Pix3.Rooms.slnx` (zero warnings) and `dotnet test Pix3.Rooms.slnx` before declaring anything done. Performance claims need a `tools/Pix3.Rooms.LoadGen` run with numbers, not reasoning.
